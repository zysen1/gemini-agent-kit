# 验证范围与状态

本仓库提供工具和执行流程。发布仓库本身不代表已经验证读者账号、订阅或全部客户端。

## 三层证据

| 层级 | 如何取得 | 能证明什么 |
| --- | --- | --- |
| 程序模拟测试 | `python3 -m unittest discover -s tests -v` | 本地 fixture 下的协议、参数、错误处理等行为 |
| 真实网关检查 | `verify --model ... --output ...` | 当前来源在短文字和工具往返检查中的实际响应 |
| 客户端真实任务 | 在目标客户端执行任务、检查产物、改变输入复验 | 该客户端在该环境下实际完成工作 |

fixture 不是 Gemini，不消耗真实来源额度。CI 通过不得宣传成模型或所有 Agent 已经跑通。

## 当前实现边界

| 功能 | 已有实现 | 仍需运行时验证 |
| --- | --- | --- |
| 网关发现 | hello、动态 models、错误信息 | 端口、来源、鉴权是否可用 |
| Chat Completions | 短文本和带 nonce 的工具往返 | 真实模型是否接受这些字段并通过检查 |
| Codex CLI | 独立 Responses provider 启动器 | Responses 兼容性、客户端工具与真实文件任务 |
| WorkBuddy | 配置计划与当前原生 adapter 指引 | 安装版本、任务选中模型、真实产物 |
| Muse / Grok Bot | stdio MCP `ask_gemini` 工具 | 具体产品连接器、执行环境、真实调用 |
| HTTP MCP | 未实现 | 需宿主支持的命令入口或额外兼容部署 |
| Codex 桌面全局切换 | CLI 启动器不实现 | 如使用 Magpie 原生路线，需单独验收 |

## 写自己的验收记录

每轮用一个新文件名；CLI 不覆盖原报告：

```sh
python3 scripts/agent_kit.py verify --model "完整模型 ID" --output reports/gateway-check-01.json
```

报告包括请求型号、网关自报型号、usage、测试结果和耗时；成功仍保留 `client_end_to_end_verified: false`，因为这项检查没有操作客户端。

为每个客户端补充：测试时间、客户端版本、网关版本、精确模型 ID、接入方式、输入、产物、第二次改变输入的结果，以及失败原因。不记录账号、密钥或私有材料。

成功率要带分母与范围。例如“该客户端 3 次短任务成功 2 次”，不要只写“成功率 100%”。服务中断、额度不足、权限缺失和协议错误应分开记录。

## 常见阻塞

| 现象 | 下一步 |
| --- | --- |
| `NETWORK_ERROR` | 确认网关已启动、端口正确、客户端与网关处于可互通的环境 |
| `MODEL_REQUIRED` | 从目录复制完整 ID，显式传 `--model` |
| `MODEL_NOT_FOUND` | 刷新目录，核对来源和权限；程序没有自动换模型 |
| `MISSING_GATEWAY_KEY` | 在当前执行环境安全设置远程网关凭据 |
| `HTTP_ERROR` / `UPSTREAM_ERROR` | 检查脱敏错误；区分鉴权、额度、来源与协议问题 |
| `TOOL_CALL_MISSING` | 文字可能可用，但工具能力尚未通过；检查源模型与转换支持 |
| `OUTPUT_EXISTS` | 使用新报告名，保留之前的结果 |
| 网关通过、客户端失败 | 检查具体协议、选中模型、重启要求和客户端自身配置 |

只有实际完成的步骤才标记通过。用户登录尚未完成时，交付已做配置和明确下一步，不生成虚假的成功截图。

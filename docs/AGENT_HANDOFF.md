# Agent 收到仓库链接后怎么做

适用于 Muse、GrokBot、Codex、WorkBuddy、豆包工作及其他 Agent。先读仓库根目录 [AGENTS.md](../AGENTS.md)，再按下面流程执行；不要只向用户复述安装说明。

## 1. 判断你能在哪里执行

先用当前工具确认，不凭产品名字猜测：

| 当前能力 | 直接执行的路线 |
| --- | --- |
| 能在用户电脑运行命令、写文件 | 在该电脑克隆仓库、检查 Python 3.11+、启动面板 |
| 只能在自己的虚拟机运行命令 | 检查网关是否已在同一虚拟机；可复用则直接接入，否则在该环境部署支持的组件 |
| 能使用已有的自定义模型或 MCP / HTTP 连接器 | 先确认连接器的执行位置及已有网关地址，再配置 |
| 只能读写已授权的用户设备文件 | 本机另需一个 worker；按 [文件桥](FILE_BRIDGE.md) 交接启动，自己负责写请求、读结果 |
| 只有聊天，没有以上入口 | 给出下方「本机交接口令」，明确尚未安装；不要虚构工具或已完成状态 |

云端、虚拟机和用户电脑各自有自己的 `127.0.0.1`。只有网关与调用工具同环境时才填写回环地址。不要为连通直接把面板暴露到公网。

## 2. 把本机服务准备好

已有授权的 Magpie / Manager 或兼容网关时，优先复用其实际地址，不重新安装整套服务。使用本仓库默认面板时：

```sh
git clone https://github.com/zysen1/gemini-agent-kit.git
cd gemini-agent-kit
python3 scripts/kit_app.py --open
```

已存在仓库则先检查是否有用户改动，再更新；不要覆盖改动。Windows 使用可用的 Python 3.11+ 解释器，例如 `py -3`，或双击仓库启动器。

面板启动后完成「准备并启动」。无来源时，让用户在本机面板输入其授权账号的 Refresh Token，等待期间继续准备目标客户端的配置位置与备份。已有 Manager 通过显式 `--connect-manager-config` 复用网关字段；不要重新索要 Token。平台安装器必须由用户完成的步骤，要交接准确入口，完成后继续。

网关需要持续运行。在即将关闭的 Agent 进程中启动服务时，先转移到独立终端或用户级后台服务，并记录停止方式。不要结束用户原有服务，也不为本任务自动重启整个 Agent。

## 3. 把实际目标 Agent 接好

用户已经指定目标时直接执行；未指定时先交付可用 API，再只问一次要连哪个产品。用户明确要求“接入你自己”时，以当前 Agent 的实际能力选路线。

1. 从实际 `/v1/models` 获取完整型号，不硬编码某个 Gemini 版本。没有目录或权限时报告原因，不能用别的模型冒充。
2. 使用面板给出的 Base URL、型号和 API Key。密钥通过本机配置或私密环境注入，不输出到聊天、报告或截图。
3. 自定义模型走 OpenAI API；只有命令工具时直接用 `ask`，不必安装 MCP；可用 MCP 的产品配置 `ask_gemini`；有授权设备文件工具的产品配置文件桥。只新增用户要连接的来源或工具，修改前备份，保留原默认模型与其他设置。
4. Codex 桌面可用面板的可选配置入口：先预览，再添加来源，需要重启/新会话选择时明确交接。Codex CLI 可用 `launch-codex`。不要把两者混写成同一个验收结果。
5. 如用户要完成真实任务，先做一次短小任务并检查返回；遇到来源权限、限流或工具不支持，说明具体层次，不反复盲试。用户只要部署或配置时无需额外消耗额度。

具体字段和各产品接法见 [CLIENTS.md](CLIENTS.md)。生成 `plan` 只是中间步骤，能实际配置的部分要继续完成。面板默认不加固定请求等待；只尊重上游返回的冷却时间，不叠加可选排队代理。

有命令执行能力时，直接写任务文件并调用一次：

```sh
python3 scripts/agent_kit.py ask --base-url http://127.0.0.1:8787/v1 --model "实际目录完整 ID" --prompt-file task.txt --output reports/reply-01.json
```

读取输出 JSON 的 `text` 完成后续产物。`task.txt` 使用 UTF-8，密钥来自私密环境，输出文件使用新名称；不会覆盖旧成果或自动重试。

需要长期 MCP 工具入口时，通用计划可这样生成：

```sh
python3 scripts/agent_kit.py plan --client generic --base-url http://127.0.0.1:8787/v1 --model "实际目录完整 ID" --runtime-script "/absolute/path/to/gemini-agent-kit/scripts/agent_kit.py" --output reports/generic-plan-01.json
```

`--client muse`、`grokbot`、`doubao` 也可生成对应名称的工具计划。这表示仓库能够生成标准连接参数，产品是否接受该连接器仍须检查；不代表已为封闭产品增加接口或替换其主模型。

## 4. 简洁交付

告诉用户：接入哪个 Agent、采用直连还是外援、选择哪个完整型号、怎么使用、怎么停止或恢复。把已完成配置和真实任务结果分开；没有运行真实任务就写「配置完成，尚未实测」，不要宣称全平台已经跑通。

例如：「已给 WorkBuddy 新增 Gemini 来源，原默认模型保留。新任务选择该来源即可使用；本次只完成配置，没有调用模型。需要恢复时移除这次新增项。」必须替换为实际完成状态，不可照抄当作成功证据。

## 本机交接口令

当前 Agent 没有本机执行能力时，给用户复制这段到一个能操作本机的 Agent；明确它是后续交接，不是当前已经完成：

```text
读取 https://github.com/zysen1/gemini-agent-kit 的 AGENTS.md。
帮我在这台电脑部署并启动面板，优先复用已有授权网关。
账号只让我在本机输入，准备好后按 docs/CLIENTS.md
把 API 或 ask_gemini 工具接到我指定的 Agent。
备份后只新增必要配置，保留原默认模型，交付使用和恢复方法。
```

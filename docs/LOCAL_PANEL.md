# 本机面板：三步接入

这是仓库自己的界面。它负责账号导入与管理、显示权益与模型、提供本机 API、备份并添加 Codex 配置；账号连接与上游协议由独立安装的社区组件 Antigravity Tools 处理。

## 打开面板

需要 **Python 3.11+**。Mac 双击仓库里的 `启动面板.command`，Windows 双击 `启动面板.bat`。启动器只检查已有 Python 并启动面板，不会自动安装 Python 或更改系统设置。缺少 Python 时，可让执行 Agent 安装，或使用 [Python 官方下载](https://www.python.org/downloads/)。

也可以在仓库目录运行：

```sh
python3 scripts/kit_app.py --open
```

Windows 可用 `py -3 scripts/kit_app.py --open`。浏览器打开 **http://127.0.0.1:8787**；地址使用 `127.0.0.1`，不是公网服务。原有 CLI 仍支持 Python 3.10+，图形面板需要 3.11+。

## 1. 准备服务

点击「准备并启动」。Mac 优先使用已安装的 5.0.3；没有则下载对应架构的官方归档。Linux 下载对应架构的官方 AppImage。程序会核验固定 SHA256，再启动独立进程；Linux 仍需具备该组件所需的系统动态库。

Windows 不静默安装软件。按提示从 [官方 v5.0.3 Release](https://github.com/lbjlaq/Antigravity-Manager/releases/tag/v5.0.3) 安装对应版本，然后回面板重新点击「准备并启动」。不要关闭系统安全功能来运行组件。

组件使用本工具独立的数据目录，默认监听 `127.0.0.1:8879`；面板监听 `127.0.0.1:8787`。遇到端口占用会保留原服务，不会强行结束它。

服务启动不会发起模型生成；检查模型时才会发送一次短请求。组件自动预热关闭。

## 2. 导入账号

把你已授权使用的完整 Refresh Token 填入本机页面的密码输入框，点击「导入账号」。输入内容应为 `1//` 开头的 Token，不是整行账号密码，也不是 API Key。

Token 只交给本机的所选 Manager，输入框随提交清空；本面板不会把导入内容写入请求日志或自己的状态文件。Manager 为维持登录会在自己的本机数据目录保存账号凭据，因此不要分享该目录，也不要把 Token 放进聊天、截图或仓库。

已导入账号可以查看当前返回的权益、刷新额度或移除。移除会删除该 Manager 保存的对应账号，之后需要重新导入。模型权限以当前账号真实返回为准；Pro / Ultra 名称、渠道价格或剩余额度不能替代实际可用性检查。

## 3. 连接 Codex

选择目录中的完整型号，点击「检查并准备配置」。这一步会消耗少量额度，检查一次回复并生成配置预览。它不会自动重试或换模型。遇到限流，按服务给出的冷却时间等待。

查看预览后点击「确认接入 Codex」。工具会先保存私有备份，再添加 `gemini_agent_kit` 来源，保留其他设置和当前默认模型。凭据由本机凭据助手读取；不会把密钥明文写入 Codex provider 段。

**最后请在 Codex 中完成：保存工作 → 重启客户端 → 设置中的网关（Gateways）选择 Gemini Agent Kit → 新建会话选择模型 → 执行真实文件任务。** 当前执行 Agent 若无法操作 Codex 自身窗口，这一步由你接手。配置保存成功和短请求通过，都不能替代桌面任务验收。

仅添加 provider 定义不会把所有 Gemini 型号合并到当前默认来源的模型菜单。需要先在网关设置中启用它；执行 Agent 也可在明确授权后用 `codex_desktop.apply(..., activate=True)` 临时设置顶层来源和型号，并保存新的回执。演示结束按相反顺序恢复每次变更。

一个简单的验收任务：给 Codex 一份真实活动信息，请它生成三个开头并保存 `draft.txt`；检查文件后，修改活动信息再试一次。记录所选型号、产物和实际成功次数，不能用“你是什么模型”的回答鉴定模型来源。

## 已经有 Manager：交给 Agent 复用

让 Agent 明确指定你授权的 Manager 配置文件，而不是再导入账号。例如：

```sh
python3 scripts/kit_app.py --connect-manager-config "$HOME/.antigravity_tools/gui_config.json" --open
```

这是常见路径示例，实际路径需由你或 Agent 确认。面板只读取其中的网关端口和鉴权字段，不读取账号 Token。首次需显式指定，之后本机私有状态会记住这个选择。不要打印整份配置。

已有本机串行代理时，可另外指定 `--inference-origin http://127.0.0.1:8046`。这是高级选项；不要把面板自身 `8787` 设为上游。复用的原服务不会被面板的停止按钮结束。

## 其他 Agent 与本机 API

面板 API 地址默认是 `http://127.0.0.1:8787/v1`，使用鉴权。页面可复制地址与型号，密钥不显示在页面；Codex 通过已配置的本机凭据助手获得访问凭据。其他客户端的凭据应由执行 Agent 在本机安全配置，不复制到聊天或公开示例。

WorkBuddy、Muse、Grok Bot 的接入方式见 [CLIENTS](CLIENTS.md)。不同产品支持的配置方式不同，必须逐个做真实任务。云端 Agent 的 `127.0.0.1` 是它自己的电脑，不能直接访问你电脑上的面板。

## 恢复与关闭

页面「高级选项」中可选择「恢复 Codex 原配置」。恢复前会检查文件是否在配置后又被修改；发生冲突时保留后续修改，不覆盖它们。私有备份与回执位于 `~/.codex/.gemini-agent-kit-backups/`，不要公开分享。

使用时保留启动窗口。按 `Ctrl+C` 关闭面板，会停止它自己启动的 Manager 进程；复用的现有 Manager 会保留。仅关闭浏览器标签不会停止服务。停止服务前先结束正在调用它的 Agent 任务。

私有数据默认保存在：

| 系统 | 位置 |
| --- | --- |
| macOS | `~/Library/Application Support/Gemini Agent Kit/` |
| Windows | `%LOCALAPPDATA%\Gemini Agent Kit\` |
| Linux | `~/.local/share/gemini-agent-kit/` |

面板状态、组件数据、账号凭据和日志属于私有数据，不属于可发布的视频素材。
